Panduan Integrasi untuk Developer

Engine ini memeriksa kualitas foto POD/paket (buram, pecah, gelap, teks tidak terbaca), memperbaiki pencahayaan secara aman bila memungkinkan, mengompres ke < 1 MB, dan menyediakan bukti pengiriman untuk penagihan. Halaman ini cukup untuk mulai integrasi. Detail lengkap ada di docs/integration-guide.md dan Swagger (bisa dicoba langsung).

Semua contoh di halaman ini otomatis memakai base URL server ini:

1. Aturan emas

Jangan pernah membuat proses kurir menunggu atau gagal karena engine. Update status pengiriman tidak boleh bergantung pada respons engine.
Selalu pakai timeout dan fail-open. Timeout ≤ 3 detik untuk mode sinkron. Jika engine lambat/mati, lanjutkan proses seperti biasa.
API key hanya di server. Jangan menaruh API key di aplikasi Android/iOS/Flutter atau JavaScript browser. Aplikasi mobile memanggil backend Anda, backend memanggil engine.
Kirim foto asli dari kamera. Jangan kompres/resize di aplikasi (contoh imageQuality/maxWidth kecil di Flutter). Engine yang mengompres dengan aman.
Runtime wajib versi yang sudah di-patch (security release 21 Okt 2026): Node.js ≥ 22.23.4 / 24.22.1 / 26.12.1, PHP ≥ 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12.

3. Minta akses

Minta ke admin engine: kode tenant (satu per aplikasi) dan API key role app. Simpan key di env server (PQE_API_KEY). Cek key:

curl -s -H "X-API-Key: $PQE_API_KEY" {{BASE}}/v1/me

Berikan ke admin: nama bucket + folder foto Anda, 3-5 contoh object key, dan jenis foto yang dihasilkan aplikasi (pod_recipient, pod_document, package, goods, location).

5. Level 2: panggil API analisis

POST /v1/analyze menerima referensi objek SILO (JSON, paling hemat kuota kurir) atau upload file (multipart). Tambahkan ?sync=true&timeout_ms=3000 untuk menunggu hasil; lewat batas waktu tetap 202 (fail-open).

# foto sudah ada di SILO
curl -s -X POST "{{BASE}}/v1/analyze?sync=true&timeout_ms=3000" \
  -H "X-API-Key: $PQE_API_KEY" -H "Content-Type: application/json" -H "Accept-Language: id" \
  -d '{"object_key":"pod/2026/10/22/AWB123.jpg","awb":"AWB123","photo_type":"pod_recipient","courier_id":"K045"}'

# kirim file langsung
curl -s -X POST "{{BASE}}/v1/analyze?sync=true" -H "X-API-Key: $PQE_API_KEY" \
  -F "file=@foto.jpg" -F "awb=AWB123" -F "photo_type=pod_recipient"

6. Membaca hasil

{
  "id": "e350b8bd...", "status": "done",
  "verdict": "REJECT",            // PASS | WARN | REJECT
  "retake_required": true,        // true = kualitas parah, tidak bisa diperbaiki: WAJIB foto ulang
  "retake_message": "Kualitas foto tidak memenuhi syarat dan tidak bisa diperbaiki otomatis. Silakan ambil foto ulang.",
  "action": "notify",             // log | notify | reject (sesuai mode yang diatur admin)
  "reasons": [{ "code": "BLURRY", "severity": "reject", "message": "Foto buram",
                "suggestion": "Pegang HP dengan stabil, ketuk layar untuk fokus, lalu foto ulang." }],
  "evidence_eligible": false,     // apakah foto masuk bukti penagihan pelanggan
  "urls": { "processed": "https://...", "thumbnail": "https://...", "expires_in": 900 }
}
FieldArti
retake_requiredPaling penting untuk aplikasi. true = foto parah (buram berat, pecah, terlalu kecil, putih total) dan sudah dicoba diperbaiki tapi tidak bisa: minta kurir foto ulang. Gabungkan dengan action (lihat §7).
verdictPASS layak, WARN kurang ideal tapi masih terbaca (tetap disimpan & masuk evidence), REJECT tidak layak.
reasons[].codeKode stabil untuk logika aplikasi. message/suggestion sudah diterjemahkan (header Accept-Language: id|en).
reasons[].severityinfo hanya informasi (contoh EXIF_MISSING), jangan ditampilkan sebagai kesalahan.

7. Menampilkan ke kurir

KondisiYang ditampilkan aplikasi
retake_required: true + action: rejectTampilkan retake_message + suggestion dari alasan pertama, tombol Foto ulang. Sediakan jalur darurat (misal "Lapor ke SPV") agar kurir tidak terjebak.
retake_required: true + action: notifyTampilkan retake_message + saran, beri pilihan Foto ulang atau Tetap kirim.
verdict: WARN + action: notifyOpsional: tampilkan saran ringan. Foto tetap diterima.
action: log (mode shadow, atau PASS)Tidak menampilkan apa-apa.
Engine tidak tersedia / timeoutTidak menampilkan apa-apa. Lanjutkan proses.

action mengikuti mode yang diatur admin (shadow → warn → enforce), jadi aplikasi tidak perlu diubah saat mode dinaikkan. Selalu gabungkan retake_required dengan action.

8. Webhook (tanpa polling)

Admin menambahkan URL backend Anda di config tenant. Engine mengirim POST JSON saat foto selesai dianalisis (analysis.completed) atau keputusan ops berubah (review.updated), ditandatangani HMAC-SHA256. Balas 2xx secepatnya; webhook bisa terkirim lebih dari sekali (dedup pakai X-PQE-Delivery).

Route::post('/hooks/photo-quality', function (Illuminate\Http\Request $request) {
    abort_unless(PhotoQualityClient::verifyWebhook(env('PQE_WEBHOOK_SECRET'),
        $request->header('X-PQE-Timestamp'), $request->getContent(), $request->header('X-PQE-Signature')), 401);
    dispatch(new HandlePhotoQuality($request->json()->all()));
    return response()->noContent();
});
app.post("/hooks/photo-quality", express.raw({ type: "application/json" }), async (req, res) => {
  const ok = await verifyWebhook(process.env.PQE_WEBHOOK_SECRET, req.get("X-PQE-Timestamp"), req.body, req.get("X-PQE-Signature"));
  if (!ok) return res.sendStatus(401);
  res.sendStatus(204);
  const event = JSON.parse(req.body.toString("utf8"));
});
import hashlib, hmac, time

def verify(secret: str, ts: str, raw_body: bytes, signature: str) -> bool:
    if not ts or abs(time.time() - int(ts)) > 300:
        return False
    mac = hmac.new(secret.encode(), ts.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(f"sha256={mac}", signature or "")

9. Evidence pelanggan (penagihan)

Evidence berisi foto PASS dan WARN (masih terbaca). Foto REJECT tidak masuk. Skor internal tidak ditampilkan ke pelanggan.

curl -s -H "X-API-Key: $PQE_API_KEY" "{{BASE}}/v1/evidence/AWB123"                 # JSON
curl -s -H "X-API-Key: $PQE_API_KEY" -o pod-AWB123.pdf "{{BASE}}/v1/evidence/AWB123/pdf"   # PDF per resi
curl -s -X POST -H "X-API-Key: $PQE_API_KEY" -H "Content-Type: application/json" \
  -d '{"awbs":["AWB123","AWB124"]}' -o invoice.pdf "{{BASE}}/v1/evidence/batch"            # PDF per invoice
curl -s "{{BASE}}/v1/verify/<sha256>"                                                  # cek keaslian (publik)

10. Perbaikan otomatis (tanpa AI)

Foto yang gelap, terlalu terang, atau pudar diperbaiki otomatis dengan satu kurva pencahayaan global (seperti fitur Levels/Curves). Setiap hasil diverifikasi eksak: tidak ada piksel yang dikarang, tidak ada teks/angka yang ditambah atau diubah. Jika verifikasi gagal, hasil perbaikan dibuang.
  • Tidak memakai AI, tidak ada penajaman, tidak ada crop/resize pada hasil perbaikan.
  • Foto original tetap disimpan utuh; kode verifikasi (SHA-256) merujuk ke original.
  • Foto buram parah, pecah, atau terlalu kecil tidak bisa diperbaiki secara jujur, jadi engine langsung mengembalikan retake_required: true.
  • Aplikasi tidak perlu melakukan apa-apa: versi yang sudah diperbaiki otomatis ada di urls.processed.

12. Checklist sebelum go-live

  • ☐ Update status kurir tetap jalan saat engine dimatikan (uji!)
  • ☐ Semua panggilan punya timeout (≤ 3 dtk sync) dan fail-open
  • ☐ API key hanya di env server, tidak di aplikasi mobile/browser/git
  • ☐ Foto dikirim asli dari kamera (tanpa kompres di aplikasi)
  • ☐ Metadata awb, photo-type, courier-id, customer-id terkirim
  • ☐ retake_required ditangani di aplikasi kurir bersama action (tampilkan pesan + tombol foto ulang; mode shadow tidak mengganggu kurir)
  • ☐ Webhook: tanda tangan diverifikasi, balas 2xx cepat, idempotent
  • ☐ Runtime Node.js/PHP versi patch 21 Okt 2026
